# Вариант: свой сервер с Docker и Caddy

Этот вариант для тех, кто умеет обслуживать VPS. Основная [инструкция Vercel](../../README.md) проще. Здесь используется тот же `api/index.py`; Caddy получает HTTPS-сертификат и передаёт запросы Python-серверу. У вас должны быть VPS в регионе, где допускается OpenAI API, домен, DNS-запись A/AAAA на сервер, открытые порты 80 и 443 и установленный Docker Compose.

## Шаги

1. Скачайте **свой форк** репозитория на сервер, перейдите в его корень.
2. Создайте файл `.env` рядом с `.env.example`. Впишите туда реальные `OPENAI_API_KEY`, `ALICE_WEBHOOK_TOKEN`, `ALICE_SKILL_ID`, `DOMAIN`. Не публикуйте `.env` и ограничьте доступ к нему на сервере. `OPENAI_MODEL` можно оставить `gpt-6-luna`.
3. Из корня репозитория выполните `docker compose -f alternatives/docker/compose.yaml up -d --build`.
4. Убедитесь, что `https://ВАШ_ДОМЕН/api` отвечает по HTTPS. GET вернёт `405` — это ожидаемо.
5. В Яндекс Диалогах задайте URL `https://ВАШ_ДОМЕН/api?token=ВАШ_СЕКРЕТ` и проверьте навык. Секрет должен совпадать с `ALICE_WEBHOOK_TOKEN`.

Для обновления получите новые файлы из своего форка и повторите шаг 3. Доступ к `.env`, обновления системы, резервирование DNS и контроль расходов остаются вашей задачей. Не выводите полный URL с токеном в общедоступные журналы.
